# YOLO Vietnamese Food Recognition — Rescue V1\n\n## Goal\n\nThe rescue build must provide real local computer-vision inference while keeping\ntraining provenance academically defensible. YOLO recognizes visual classes; it\ndoes not infer calories directly. Java later maps a recognized class to the\nauthoritative Ingredient or Recipe catalog and nutrition data.\n\n## Ingredient detector V1\n\nThe first trainable detector uses twelve classes. User-facing names are entirely\nVietnamese while stable ASCII codes are retained internally for API/database\nmapping.\n\n| ID | Code | Vietnamese name |\n| ---: | --- | --- |\n| 0 | TRUNG_GA | Trứng gà |\n| 1 | CA_CHUA | Cà chua |\n| 2 | CA_ROT | Cà rốt |\n| 3 | HANH_TAY | Hành tây |\n| 4 | TOI | Tỏi |\n| 5 | DUA_CHUOT | Dưa chuột |\n| 6 | KHOAI_TAY | Khoai tây |\n| 7 | THIT_GA | Thịt gà |\n| 8 | THIT_LON | Thịt lợn |\n| 9 | THIT_BO | Thịt bò |\n| 10 | CA | Cá |\n| 11 | BAP_CAI | Bắp cải |\n\nThe detector is fine-tuned from pretrained YOLO11n weights. This is transfer\nlearning, not training from random initialization.\n\n## Dataset rule\n\nDo not rename a source data.yaml and assume the numeric labels changed with it.\nThe preparation script reads the original class ids, keeps only the twelve\nsupported classes, remaps them to dense ids 0..11, validates normalized YOLO\nboxes and writes a new UTF-8 data.yaml with Vietnamese class names.\n\nA candidate source dataset must actually contain all twelve classes. The\npreparation step fails closed if any promised class is absent.\n\nVerified public candidates as of 2026-10-06:\n\n- Roboflow Universe temp_project_7: about 1.6k images, 20 classes, CC BY 4.0.\n  Its published class list includes all twelve rescue classes. This is the fast\n  overnight option.\n- Roboflow Universe food ingredients (my-workspace-idgwe): about 40.4k images,\n  20 classes, CC BY 4.0. Its published class list also includes all twelve\n  rescue classes. This is the larger follow-up dataset.\n\nRecord the exact dataset/version URL and license used for the final trained\ncheckpoint in the experiment report.\n\n## Preparation\n\nAfter exporting a source dataset in Ultralytics YOLO format, run:\n\n    python ai_service/training/prepare_ingredient_dataset.py --source-yaml <source-folder>/data.yaml\n\nExpected output:\n\n    ai_service/training/datasets/vietnamese_ingredients_v1/\n      data.yaml\n      images/train/\n      images/val/\n      images/test/     # when the source has a test split\n      labels/train/\n      labels/val/\n      labels/test/\n\nInspect the printed object counts before training. A class with zero objects is\nan invalid dataset for this V1 contract.\n\n## Training on the rescue laptop\n\nThe verified local machine has an RTX 2050 with 4 GiB VRAM. Start with YOLO11n,\n640 px input and batch 4:\n\n    python ai_service/training/train_ingredients.py\n\nIf CUDA reports out-of-memory, reduce only the batch first:\n\n    python ai_service/training/train_ingredients.py --batch 2\n\nIf memory is still insufficient, use 512 px with batch 2. Do not silently fall\nback to CPU for the overnight rescue run.\n\nUltralytics writes training arguments, plots and weights under\nai_service/training/runs/ingredients_yolo11n_v1/. Keep these artifacts as\nexperiment evidence.\n\n## Dish detector\n\nDish recognition remains a separate model boundary because finished dishes and\nraw ingredients have different visual distributions. VietFood67 is the preferred\nVietnamese-dish reference dataset/checkpoint: its authors report 33,003 images\nacross 68 classes and a YOLOv10 model with mAP50 around 0.92. The project states\nthat VietFood67 is free for research/educational use with citation and prohibits\ncommercial use or redistribution.\n\nIf the rescue build integrates a pretrained VietFood67 checkpoint, describe it\nas an externally trained checkpoint. Do not claim that the team trained it.\n\n## Runtime direction\n\n    image\n      -> YOLO detector\n      -> class id + Vietnamese name + confidence + bounding box\n      -> Java catalog mapping\n      -> Ingredient / Recipe entity\n      -> nutrition, pantry and recommendation workflows\n\nThis keeps computer vision separate from authoritative business and nutrition\nstate.\n
